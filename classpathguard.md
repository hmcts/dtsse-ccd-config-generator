# Jackson 3 classpath compatibility guard

## Purpose

Extend the existing `jackson3CompatibilityGuard` with a bytecode scan that detects
Jackson 2 databind metadata and APIs in compiled application classes and dependency
JARs.

The existing source scan remains the first line of defence. The classpath scan closes
the gaps that source scanning cannot cover:

- annotations generated by processors such as Lombok `@Jacksonized`;
- shared domain models supplied by another project;
- client DTOs supplied by a library;
- custom serializers and deserializers hidden in dependencies;
- compiled Kotlin, Groovy or generated classes whose source is not available.

The guard must identify code that can compile successfully because Jackson 2 remains
on the classpath, but whose Jackson 2 metadata is ignored when the class is processed
by a Jackson 3 mapper.

## Non-goals

The guard does not:

- prohibit Jackson 2 dependencies from existing on the classpath;
- reject `com.fasterxml.jackson.annotation.*`, which remains supported by Jackson 3;
- prove that a model round trip preserves stored JSON;
- determine statically whether every discovered class is passed to a Jackson 3 mapper;
- load application or dependency classes;
- replace end-to-end round-trip testing using representative case data.

## Gradle task

Register a new verification task:

```text
jackson3ClasspathGuard
```

`check` must depend on both:

```text
jackson3CompatibilityGuard
jackson3ClasspathGuard
```

The source guard must continue to run without compilation or dependency resolution.
The classpath guard may depend on compiled source-set outputs and resolve classpath
artifacts.

The classpath guard should scan each registered source set's compiled output. Dependency
artifacts should be de-duplicated before scanning.

## Enforcement scopes

Classpath findings are divided into three scopes.

### Project output

All compiled classes produced by the current Gradle project.

Findings in project output fail the task. This includes annotations generated by Lombok
or another annotation processor.

### First-party dependencies

Classes from:

- Gradle project dependencies;
- artifacts whose group is `com.github.hmcts`;
- artifacts whose group is `uk.gov.hmcts`.

Findings in first-party dependencies fail the task by default. These dependencies are
likely to contain shared domain models or client DTOs passed through application
serialization paths.

### Third-party dependencies

All other resolved dependency artifacts.

Third-party findings are included in the report but do not fail the task by default.
Legacy Jackson metadata inside an unrelated library does not imply that its classes are
processed by the application's Jackson 3 mapper.

The report must clearly distinguish enforced and informational findings.

## Bytecode scanning

Use ASM to inspect `.class` files without loading them.

The scanner must process:

- class files in source-set output directories;
- class files in dependency JARs;
- runtime-visible annotations;
- runtime-invisible annotations;
- class, field, method, constructor and parameter annotations;
- type annotations;
- class super types and interfaces;
- field and method descriptors;
- generic signatures;
- annotation values that reference a class.

The scanner must not execute static initializers or require the scanned classes'
dependencies to be loadable.

### Multi-release JARs

For a multi-release JAR, scan the class version selected for the active Java toolchain.
Do not report duplicate findings for both the base class and the selected versioned
class.

### Invalid artifacts

An unreadable class or JAR must fail the task with the artifact and entry name. The
scanner must not silently skip malformed inputs.

## Forbidden annotations

Report any annotation whose descriptor begins with:

```text
Lcom/fasterxml/jackson/databind/annotation/
```

Important examples include:

```text
JsonDeserialize
JsonSerialize
JsonNaming
JsonPOJOBuilder
JsonTypeIdResolver
JsonTypeResolver
JsonValueInstantiator
JsonAppend
```

This detects direct source annotations as well as annotations generated by Lombok
`@Jacksonized`.

The report should use the finding type:

```text
JACKSON2_DATABIND_ANNOTATION
```

## Forbidden API references

Report bytecode references to removed Jackson 2 APIs under:

```text
com/fasterxml/jackson/databind/
com/fasterxml/jackson/core/
com/fasterxml/jackson/datatype/
com/fasterxml/jackson/module/
```

Examples include:

```text
com/fasterxml/jackson/databind/ObjectMapper
com/fasterxml/jackson/databind/JsonDeserializer
com/fasterxml/jackson/databind/JsonSerializer
com/fasterxml/jackson/core/JsonParser
com/fasterxml/jackson/datatype/jsr310/ser/LocalDateTimeSerializer
```

References may appear in a superclass, implemented interface, method descriptor,
generic signature, annotation value or constant-pool type.

The report should use the finding type:

```text
JACKSON2_API_REFERENCE
```

The initial implementation may restrict constant-pool inspection to typed ASM visitor
events. It must not report arbitrary string constants containing a class name.

## Allowed shared annotations

Do not report references under:

```text
com/fasterxml/jackson/annotation/
```

Jackson 3 deliberately continues to use this shared annotation package. Valid examples
include:

```text
JsonAlias
JsonCreator
JsonFormat
JsonIgnore
JsonIgnoreProperties
JsonInclude
JsonProperty
JsonUnwrapped
JsonValue
```

The scanner must not recommend mechanically replacing these imports with
`tools.jackson`.

## Configuration

Expose a minimal extension:

```groovy
ccdSdk {
  jackson3ClasspathGuard {
    firstPartyGroups = ['com.github.hmcts', 'uk.gov.hmcts']
    reportThirdParty = true
    allowedFindings = [
      // Exact, reviewed exceptions only.
      'com.github.hmcts:example-client:1.2.3:uk.gov.hmcts.example.LegacyDto'
    ]
  }
}
```

Defaults:

```text
firstPartyGroups = ["com.github.hmcts", "uk.gov.hmcts"]
reportThirdParty = true
allowedFindings = []
```

Allow-list entries must be exact. Wildcard package or artifact exclusions are not
supported.

Each allow-list entry must identify:

- component or project;
- class name;
- optionally the exact annotation or API descriptor.

The report must show allowed findings separately so that an exception cannot make the
risk invisible.

## Report

Write:

```text
build/reports/jackson-compatibility/classpath-report.txt
```

Each finding must include:

```text
scope
component
class
member, when applicable
finding type
legacy annotation or API
enforcement status
```

Example:

```text
ERROR [PROJECT_OUTPUT] uk.gov.hmcts.example.CaseData
  JACKSON2_DATABIND_ANNOTATION
  class annotation com.fasterxml.jackson.databind.annotation.JsonDeserialize

ERROR [FIRST_PARTY_DEPENDENCY] com.github.hmcts:example-client:1.2.3
  uk.gov.hmcts.example.PaymentCallback
  JACKSON2_DATABIND_ANNOTATION
  class annotation com.fasterxml.jackson.databind.annotation.JsonNaming

INFO [THIRD_PARTY_DEPENDENCY] org.example:legacy-json-client:4.5.6
  org.example.internal.Payload
  JACKSON2_API_REFERENCE
  field mapper: com.fasterxml.jackson.databind.ObjectMapper
```

The task summary must include:

- number of project classes scanned;
- number of dependency JARs scanned;
- number of first-party and third-party classes scanned;
- enforced finding count;
- informational finding count;
- allowed finding count;
- report path.

## Failure behaviour

The task fails when there is at least one non-allowed finding in:

- project output;
- a Gradle project dependency;
- a configured first-party dependency group.

Third-party findings do not fail the task unless their group is added to
`firstPartyGroups`.

The failure message must explain that Jackson 2 bytecode can compile and load while its
databind annotations are ignored by Jackson 3.

## Performance and Gradle correctness

The task should be cacheable.

Inputs must include:

- compiled source-set class directories;
- resolved classpath artifacts;
- first-party group configuration;
- allow-list entries;
- active Java toolchain version;
- scanner implementation version.

The report file is the task output.

JARs must be opened directly rather than unpacked to the project directory. Scan each
unique artifact once, even when it appears in multiple source-set classpaths.

The scanner should use Gradle artifact metadata to retain component coordinates in
diagnostics. File names alone are insufficient.

## Tests

### Project output

A functional test must compile a class containing:

```java
@com.fasterxml.jackson.databind.annotation.JsonNaming(...)
```

`jackson3ClasspathGuard` and `check` must fail and report the compiled class.

### Generated `@Jacksonized` annotations

A functional test must compile a builder using a Lombok version that generates Jackson
2 annotations:

```java
@lombok.Builder
@lombok.extern.jackson.Jacksonized
class Request {
    String value;
}
```

The source compatibility guard may pass when correctly configured, but the classpath
guard must detect the generated Jackson 2 `JsonDeserialize` or `JsonPOJOBuilder`
annotation.

### Custom deserializer

A functional test must compile:

```java
@com.fasterxml.jackson.databind.annotation.JsonDeserialize(using = LegacyDeserializer.class)
class Request {}

class LegacyDeserializer
    extends com.fasterxml.jackson.databind.JsonDeserializer<Request> {}
```

The report must include both the annotation and the Jackson 2 superclass reference.

### Shared annotations

A class using only:

```java
com.fasterxml.jackson.annotation.JsonIgnoreProperties
com.fasterxml.jackson.annotation.JsonProperty
```

must pass.

### First-party dependency

A TestKit fixture must consume a local Maven or Gradle project dependency containing a
legacy databind annotation. The consuming project's classpath guard must fail and name
the dependency component and class.

### Third-party dependency

A fixture with the same bytecode under an unconfigured third-party group must succeed
and report an informational finding.

### Allow list

An exact allow-list entry must make its matching finding non-fatal and visible in the
report. It must not suppress findings for another class or another version of the same
artifact.

### Malformed artifact

An unreadable class entry must fail explicitly rather than being skipped.

### No dependency class loading

A fixture JAR containing a class whose superclass is absent must still be scanned and
reported without attempting to load that class.

## Acceptance criteria

The implementation is complete when:

1. `check` detects legacy Jackson 2 annotations generated into project bytecode.
2. `check` detects legacy Jackson 2 annotations and API references in first-party
   dependency bytecode.
3. Shared `com.fasterxml.jackson.annotation` annotations pass.
4. Jackson 2 dependencies that contain no relevant model or API bytecode findings can
   coexist.
5. Third-party findings are visible without blocking by default.
6. Diagnostics identify the component, class, member and legacy API.
7. The scanner never loads application classes.
8. The task is cacheable and produces stable output.
9. Existing source compatibility guard behaviour remains unchanged.
10. The report explicitly states that bytecode scanning does not replace JSON
    round-trip testing.
